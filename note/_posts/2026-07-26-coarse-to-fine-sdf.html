--- title: "Coarse-to-Fine SDF" layout: post related: - deep-sdf - latent-shapes-experiment - linear-interpolation - voxels-to-graph ---
  • A dense grid is mostly waste
    • A signed distance function (SDF) answers one question per point: how far is the surface, and is the point inside (negative) or outside (positive). The shape is where the answer is zero. Every figure below draws inside points red and outside points blue

    • To get a mesh, the function is sampled on an \(R \times R \times R\) grid, and marching cubes emits triangles wherever the sign changes between cell corners
    • Where on the edge? Write a point on it as \(p(t) = p_0 + t(p_1 - p_0)\), let the value change linearly, \(v(t) = v_0 + t(v_1 - v_0)\), and ask for the zero:
      \[ 0 = v_0 + t(v_1 - v_0) \quad \Longrightarrow \quad t = \frac{v_0}{v_0 - v_1} \]
      One \(t\), used twice: solved from the two values, then spent on the position \(p_0 + t(p_1 - p_0)\). So the vertex lands nearer the corner whose value is closer to zero, not at the middle

    • The grid sets the bill. \(R = 128\) is 2,097,152 queries, and doubling \(R\) multiplies that by eight. When the SDF is a neural decoder, those queries are nearly the whole cost
    • A surface is 2D inside a 3D grid. Cost grows like \(R^3\), but the answer only lives on \(R^2\) cells, so almost every query reports empty space

  • Refine only near the surface
    • Start on a cheap grid, then at each finer level re-evaluate only the cells the surface could pass through. Halving \(R = 128\) down to a floor of 16 gives the ladder \(16 \rightarrow 32 \rightarrow 64 \rightarrow 128\)
    • Could pass through is wider than does pass through. A cell is kept when its corners change sign, and also when any corner lies within \(\tau h\) of the surface, \(h\) being the cell size. The band is what saves thin parts: a feature thinner than one cell can leave all eight corners outside, and a cell dropped once never comes back. latent-shapes uses \(\tau = 2.5\) and then grows the mask by one cell; the figure below uses a narrower \(\tau = 0.5\) so the picture stays readable
    • Only the coarsest level samples everything, and it is small on purpose: \(16^3\) is 4,096 points, about 0.2% of the dense grid at \(R = 128\)
    • Every level ends with marching cubes, so each one produces a complete mesh, and the loop repeats until the finest level is reached
    • The result behaves like an octree, but it is not stored as one. Each level allocates a full uniform grid, and only the decoder calls are restricted; unmarked points copy the coarse value. Marching cubes wants a regular grid, and the decoder is where the cost is, so a sparse structure would buy little
    • Meshing the bunny this way samples 42,034 points against 274,625 for a dense \(64^3\) grid, and the mesh that comes out is identical to the dense one, vertex for vertex, at 14,706 triangles
